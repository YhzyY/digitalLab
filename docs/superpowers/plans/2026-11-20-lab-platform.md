# 数字孪生城市虚拟仿真实验平台开发计划

## 当前实施版本

先交付可直接打开的静态实验网页，运行时采用原生 HTML、CSS、JavaScript 和随项目提供的 Three.js。场景从空白开始，20 步依次展示范围、道路、建筑、配套设施、观测与态势变化。使用虚拟的实景风格资产和合成观测。通过透视相机、三维对象和连续仿真呈现实验影响，包括运动的车流、设备与观测传输、积水水面及候选烟雾。进度保存在本机浏览器。正式 Token 会话、云端存档与课堂部署沿用下文联调安排，运行时框架以本段选型为准。

**目标**：学生从带 Token 的链接进入受限首页，点击三个模块进行训练，退出后可以从各模块的上次操作位置继续。

**架构**：Cloudflare 托管网页和 API。浏览器渲染三维街区并执行仿真。D1 保存身份关联、模块进度及运行索引，R2 保存版本化案例资源与较大成果，IndexedDB 保存本机待同步草稿。

**技术栈**：React、TypeScript、Vite、CesiumJS、浏览器 Web Workers、ONNX Runtime Web、Cloudflare Workers Static Assets、D1、R2、Wrangler。已有 Pages 项目与接入配置可在确认后复用。

**需求依据**：[教学设计 v2.2](../../../数字孪生城市多源数据融合与智能态势感知虚拟仿真实验v2.2.docx)及本次会话确认的网页范围。进度与验收证据见[开发台账](../../../tasks/todo.md)。

## 产品范围和验收约定

- 使用两类页面。首页需有效会话，展示实验简介、目标、场景预览和三个模块的进度及入口。三个模块共用训练页模板，结果对照、历史和导出在训练页内完成。
- 三个模块名称固定为「数字孪生城市搭建环节」「多源数据融合环节」「智能态势感知数据处理环节」。每个模块可以直接进入，涉及前序产物时提供该学生已保存的结果和已授权的课程示例。运行记录写明实际使用的数据版本。
- 三个模块分别保存当前步骤、步骤完成状态、配置、选中对象、时间位置和已选运行。恢复目标是操作现场。浏览器计算中断时恢复运行前参数，可重新执行。
- 三维街区是训练反馈的主视图。每项会改变孪生对象关联、观测或判定结果的操作，都应在三维场景中呈现对应变化；计算型操作在成功运行后更新。地图、图表和证据面板读取同一运行版本，按对象 ID 和时间窗口同步更新。
- 三维街区采用现实风格的虚拟模型，自制彩色建筑、道路、路口、标线及绿化。近景可观察建筑立面、线条、投影与车体细节，远景可验证整体布局和监测状态。
- 项目范围为学生仿真网页。实验算法包含车辆识别；教学管理和 AI 教学指导均不进入本计划。第 16 步以「结果证据核验」作为原型中的拟议替代题，正式课件发布前由课程组确认。
- 首版用一个虚拟街区和合成案例验证流程。开发阶段使用测试身份，正式课堂上线前完成入口联调和虚拟教学案例校核。

## 目录与验证方式

| 计划路径 | 职责 |
|---|---|
| `src/app/` | 首页、训练页模板、路由、共用保存状态 |
| `src/labs/` | 三个模块的任务定义、操作面板和实验引擎 |
| `src/progress/` | IndexedDB 草稿、同步队列、进度恢复 |
| `worker/`、`migrations/` | Token 会话、进度与成果接口、D1 迁移 |
| `fixtures/` | 合成街区、视频观测、边界样本及预期结果 |
| `tests/`、`e2e/` | 算法测试、Worker 集成测试、浏览器流程测试 |

由 DEV-01 建立统一命令。`npm run dev` 启动本地应用，`npm run build` 校验生产构建，`npm test` 执行 Vitest 单元与集成测试，`npm run test:e2e` 执行 Playwright 浏览器流程。首次提交实现前确认版本控制位置，当前目录尚无 Git 仓库。

## 三维场景交互与画面验收

| 训练模块 | 可复验的学生操作 | 场景中可观察的结果 |
|---|---|---|
| 数字孪生城市搭建环节 | 将检测器从路段 A 改绑至路段 B，应用并回放同一时段 | 设备关联线或绑定标记从 A 切换到 B，观测状态跟随新绑定，旧关联同步消失 |
| 多源数据融合环节 | 切换到另一有效数据来源，运行一个已知会改变计数的案例 | 对应路段的流量标注及专题色带随计数更新，点击路段可核对当前来源和质量标记 |
| 智能态势感知数据处理环节 | 将一条关键水位观测设为缺测并运行 | 指定路段从原积水等级切换到「未知」样式，旧积水覆盖消失。前后对照可切回原运行 |

用单独的标记、轮廓或半透明专题层展示实验变化，保留可辨识的实景底色，并通过图例和文字区分状态。配置发生变化但尚未运行时，界面区分草稿与当前显示的运行。复验涵盖结果确实变化、结果保持一致和运行失败三种情况。失败时保留上次成功画面并提示错误。断点恢复时，场景重载最近已选运行及时间位置。

画面验收保留街区全景、路口近景和单体选中三张参考画面，检查建筑立面及屋顶纹理、路面及车道标线、绿化层次、尺度和材质，以及叠加状态后对象是否仍可辨认。照片纹理或实景网格与交互对象可分层加载，通过稳定对象 ID 将模型位置与可选路段、建筑和设施关联。

## 第一阶段 访问到续做

### DEV-01 本地工程与两类页面

- 在 `src/app/` 搭建受限首页与共用训练页。用三个稳定模块标识 `city-twin`、`data-fusion`、`situation-awareness` 注册路由和名称。同步初始化构建及测试命令。
- 用合成 GeoJSON 街区提供道路、设施和少量观测。验收为测试身份进入首页后可点开三个模块并返回，直接访问模块地址会执行会话检查，生产构建成功。

### DEV-02 Token 与学生会话

- 在 `worker/session.ts` 建立 Token 验证适配器，输出稳定学生标识。验证后发放安全会话 Cookie，跳转到不带 Token 的地址。首页、模块路由和进度 API 按会话授权。真实 Token 接口细节由 DEP-01 提供。
- 用测试发放器覆盖有效、无效、过期、不同学生、同一学生更换 Token。验收为同一学生复用原进度，越权读取被拒绝，重定向后地址栏与应用日志中均无原始 Token。

### DEV-03 自动保存与恢复

- 在 `src/progress/` 和 `worker/progress.ts` 实现按学生、实验版本、模块保存。保存请求使用基准版本和操作编号。草稿先持久化到 IndexedDB，再同步到 D1。界面明确展示保存中、云端已保存和本机待同步。
- 用双浏览器上下文验证同设备刷新、跨设备恢复、断网续做、恢复联网后补传、重复请求及并发冲突。验收为大文件上传成功后才登记为可跨设备恢复的运行，任何旧保存都不会静默覆盖新版本。

### DEV-04 单街区纵向原型

- 在 `src/labs/city-twin/` 接入 CesiumJS，打通道路和设施选择、设备绑定、对象状态更新、时间轴及原始记录查询。
- 用一小块彩色、写实街区样板验证纹理、对象选择及专题图层叠加。保存三张参考画面；实景素材未到时先使用自制带纹理样板，后续替换时沿用同一交互与画面验收标准。
- 阶段验收为学生用有效测试链接进入首页，修改设备绑定并保存，退出后重新进入同一模块，恢复步骤与配置，能继续运行并追查结果。另一台浏览器使用同身份恢复到最近云端确认的版本。

## 第二阶段 补齐三个模块

### DEV-05 数字孪生城市搭建环节

- 在 `src/labs/city-twin/` 补齐数据字典、来源说明、缺失和重复处理、坐标转换、乱序处理、编码和歧义匹配、观测到孪生对象映射。
- 使用包含重复设备、同名对象、异常坐标及乱序时间的固定样本验证。验收为学生能定位歧义、修正匹配并从变化后的地图状态查回观测，关联结果可被下一模块引用。

### DEV-06 多源数据融合环节

- 在 `src/labs/data-fusion/` 实现短视频设置计数线和方向、轻量模型检测与跟踪、过线计数、检测器接入、质量选源、单源与双源对照、移除来源对照和新增设备接入。先在代表性机房电脑测量 WASM 视频推理，再确定视频及模型规格。
- 按断面、方向和左闭右开的一分钟窗口对齐。用固定样本验证窗口边界、人工核验误差、零计数、单源缺测回退、双源缺测为未知和有效覆盖率。验收包括中途关闭视频任务后恢复参数并重跑。
- 将融合结果绑定到相应路段的流量标注和专题层，验证切换数据源并重跑后，地图和当前窗口的结果表一致。

### DEV-07 智能态势感知数据处理环节

- 在 `src/labs/situation-awareness/` 实现建筑火警候选事件、交通拥堵和道路积水。支持规则基线、缺测/噪声/延迟扰动、按原始证据诊断及固定测试条件复验。
- 用标注样本验证火警归组和触发证据、拥堵只取最近三个已完成窗口、积水缺测输出未知。验收为改变一条关键观测后能并排查看两次运行并查到差异依据。
- 为建筑候选火警、路段拥堵和积水提供独立的三维状态图层。验证随时间窗口或运行版本切换正确增删标记，且「未知」与正常状态可辨识。

### DEV-08 运行历史与成果

- 在共用训练页提供历史运行恢复、结果对照和导出，保存案例、场景、算法及模型版本、输入配置、随机种子和产物引用。上游结果变动后，依赖旧结果的步骤显示待复验。
- 验收为任选一个模块的两次运行，导出配置和证据，在同一版本的数据包上复现结果。若课程组确认首版须交付自编脚本和学习模型对照，由 CUR-01 形成独立验收任务再纳入发布范围。

## 第三阶段 联调与课堂验证

### DEV-09 Cloudflare 预览与真实入口联调

- 在测试环境建立独立 D1、R2 和 Worker 绑定，验证正式 Token 入口、测试环境密钥及访问域名。分别验证首屏、小数据资源、瓦片和授权视频加载。测试资源与正式学生数据使用不同环境。
- 验收为通过真实发放方生成的测试链接进入预览环境，身份隔离、存档和资源访问均正常。以校园网访问记录确认入口与资源域名可用。

### DEV-10 课堂演练与发布检查

- 演练约 100 个学生会话集中访问首页、加载场景、保存与恢复。另用机房代表性配置实测浏览器渲染和视频推理，记录首屏耗时、保存成功率、保存延迟和视频耗时。
- 按三个模块分别完成端到端验收，记录操作前后画面与对应运行。用正式街区资源复核三张参考画面和机房加载表现。发布材料包含预览链接、已验证浏览器、运行限制和回滚方式。性能阈值基于首轮实测后确定，实际访问入口、正式案例与开放前检查通过后再发布。

## 外部输入及处理顺序

- **DEP-01 真实 Token 契约**。需入口参数、Token 验证方式、失效规则、稳定学生标识和测试样例。可与 DEV-01 并行，影响 DEV-09。
- **DEP-02 虚拟教学案例校核**。核对合成街区对象 ID、样例视频轨迹、传感器记录、预期结果和规则参数。正式课堂版本使用课程组确认后的虚拟案例。
- **DEP-03 Cloudflare 联调资源**。需可使用的项目、测试域名及 D1/R2 绑定权限。影响 DEV-09 和 DEV-10。
- **CUR-01 课程细节确认**。确认最终步骤编号、第 16 步替代任务，以及自编脚本和学习模型对照是否纳入首版。该项不影响两类页面、身份访问和进度功能先行开发。
